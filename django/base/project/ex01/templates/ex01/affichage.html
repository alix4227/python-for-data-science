Le processus d’affichage d’une page web statique à partir d’un template (dans un cadre type MVC / MTV comme Django) suit une chaîne bien précise entre la requête du client et la réponse du serveur.

Lorsqu’un utilisateur accède à une URL, son navigateur envoie une requête HTTP au serveur. Cette requête est d’abord reçue par le système de routage (URL dispatcher). Son rôle est d’analyser l’URL demandée et de la faire correspondre à une vue (view) définie dans l’application.

Une fois la vue identifiée, celle-ci est exécutée. Dans le cas d’une page statique, la vue n’a généralement pas besoin d’accéder à une base de données ou d’effectuer des traitements complexes.
Elle sert principalement de point de contrôle : elle choisit le template à utiliser et peut éventuellement lui passer un contexte (souvent vide ou minimal pour du statique).

Le template est ensuite traité par le moteur de templates. Ce moteur transforme le fichier HTML “modèle” en une page HTML complète.
Même pour une page dite statique, ce mécanisme permet d’inclure des éléments réutilisables (comme des en-têtes, des menus, des blocs communs) via l’héritage ou les includes.

Une fois le template rendu, le résultat est une chaîne HTML finale.
Cette chaîne est renvoyée par la vue sous forme de réponse HTTP.
Le serveur envoie alors cette réponse au navigateur du client. Le navigateur reçoit le HTML, l’interprète et affiche la page web à l’utilisateur.

En résumé: Requête HTTP → URL routing → Vue → rendu du template → réponse HTTP → affichage dans le navigateur.
